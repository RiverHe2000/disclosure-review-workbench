# User study protocol — not yet conducted

Recruit 3–5 people familiar with financial statements. Participation is voluntary; do not publish identities. A developer's self-test is not an external user study.

Each participant completes matched tasks on different bank/year pairs: extract the five metrics, identify their date and scope, and state which comparisons are valid. Counterbalance order: half begin with PDFs and a spreadsheet; half begin with the workbench. Use different report pairs to reduce recall effects. Keep source data and task instructions identical between conditions.

Record total elapsed time, incorrect final values, context mistakes, unresolved comparisons, number of manual changes, and one short usability comment. Count parsing/inference waiting time separately and report both fresh and preprocessed conditions. Correctness is assessed against an independently human-checked answer key, not against the app's own output.

Publish paired individual results with denominators and anonymised feedback. With such a small convenience sample, describe observations and limits; do not claim universal time savings or statistical proof.
